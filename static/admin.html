  • 프로덕션 권장: 프로덕션 환경에서는 반드시 활성화하는 것을 권장합니다

  • 사용자 경험: 간단한 수학 문제로 사람과 봇을 구분하며, 시각적으로 명확한 UI 제공

ℹ️ 2차 인증 정보:
  • Google OTP (TOTP): Google Authenticator 앱과 호환되는 시간 기반 일회용 비밀번호
  • 설정 방법: 사용자 목록에서 각 사용자의 QR 코드를 스캔하여 Google Authenticator에 계정 추가
  • 로그인 방식: 2FA 활성화 시, 비밀번호 입력 후 Google Authenticator의 6자리 코드 입력 필요

    • 30초마다 갱신되는 6자리 일회용 코드
    • 시간 기반 알고리즘으로 서버와 동기화
    • 사용자별 고유 Secret Key로 보안 강화
    • ±30초 시간 오차 허용으로 안정적 인증
    • QR 코드를 통한 간편한 초기 설정
  • 보안 효과: 비밀번호 유출 시에도 추가 인증 요구로 계정 보호
  • 관리 기능: 사용자 목록에서 QR 코드 확인 및 Secret 재생성 가능

🚀 빠른 시작 가이드

1️⃣ 문서 업로드

"문서 관리" 탭에서 PDF, HWP, DOCX 파일을 업로드하여 챗봇이 참조할 수 있는 지식 베이스를 구축하세요.

2️⃣ 그룹 생성

"그룹 관리" 탭에서 문서를 주제별로 그룹화하여 효율적으로 관리하고 검색 정확도를 높이세요.

3️⃣ 조직 관리

"조직 관리" 탭에서 조직을 생성하고 사용자를 조직에 할당하여 문서 접근 권한을 관리하세요.

4️⃣ 모델 설정

"모델 설정" 탭에서 LLM 모델과 임베딩 모델을 선택하여 챗봇 성능을 최적화하세요.

5️⃣ Hybrid RAG 설정 (선택)

"시스템 설정" 탭에서 Hybrid RAG를 활성화하면 로컬 문서 + 웹 검색 + 공식 문서를 통합 검색할 수 있습니다. 웹 검색은 Tavily(클라우드) 또는 SearXNG(자체 호스팅)를 선택할 수 있습니다.

💡 시작 팁: 먼저 문서를 업로드하고 그룹화한 후, 챗봇 페이지에서 검색해보세요. Hybrid RAG는 외부 정보가 필요할 때만 활성화하세요.

📄 문서 관리 ▼

📤 문서 업로드

  • 지원 형식: PDF, HWP, HWPX, DOC, DOCX, TXT
  • 업로드 방법: "파일 선택" 버튼 클릭 → 파일 선택 → 자동 업로드
  • 자동 처리: 업로드 시 자동으로 텍스트 추출 및 임베딩 생성
  • 상태 확인: 업로드 후 문서 목록에서 "청크 수" 확인 (0이 아니면 정상)

🔍 문서 검색 및 필터링

  • 검색창 사용: 파일명, 크기, 청크 수, 날짜로 검색 가능
  • 한글 검색: 한글 파일명도 정확하게 검색 가능 (예: "신원")
  • 확장자 필터: 통계 패널에서 확장자 클릭 시 해당 형식 문서만 표시
  • 검색 초기화: 검색창 우측 ✕ 버튼으로 전체 목록 복원

📊 문서 통계

  • 전체 개수: 우측 상단에 전체 문서 수 표시
  • 확장자별 분포: 각 파일 형식별 개수와 비율(%) 표시
  • 클릭 필터링: 확장자 배지 클릭으로 즉시 필터 적용
  • 실시간 업데이트: 검색 시에도 전체 통계는 유지

🗑️ 문서 삭제

  • 개별 삭제: 문서 카드의 "🗑️ 삭제" 버튼 클릭
  • 확인 절차: 삭제 전 확인 팝업으로 실수 방지
  • 즉시 반영: 삭제 후 자동으로 목록 새로고침
  • 복구 불가: 삭제된 문서는 복구할 수 없으니 신중히 선택

💡 팁: 대용량 PDF는 업로드 및 처리에 시간이 걸릴 수 있습니다. 파일 크기가 50MB를 초과하는 경우 분할 업로드를 권장합니다.

📁 그룹 관리 ▼

🌳 그룹 생성 및 구조

  • 그룹 생성: 좌측 패널 상단 "그룹 생성" 버튼 클릭
  • 계층 구조: 최대 3단계 깊이까지 하위 그룹 생성 가능
  • 이모지 사용: 그룹 이름에 이모지를 추가하여 시각적 구분 가능
  • 이름 변경: 그룹 선택 후 "이름 변경" 버튼으로 수정

📄 문서 추가 및 관리

  • 문서 추가: 그룹 선택 → "문서 추가" 버튼 → 문서 선택 → 저장
  • 다중 선택: Ctrl 또는 Shift 키로 여러 문서 동시 추가 가능
  • 문서 제거: 그룹에서 문서 제거 시 문서 자체는 삭제되지 않음
  • 중복 추가: 하나의 문서를 여러 그룹에 동시에 포함 가능

🔍 그룹별 검색

  • 범위 지정: 특정 그룹 선택 시 해당 그룹 내 문서만 검색
  • 하위 포함: 상위 그룹 선택 시 모든 하위 그룹 문서 포함
  • 정확도 향상: 그룹화로 검색 정확도 및 속도 향상

🗑️ 그룹 삭제

  • 삭제 조건: 빈 그룹(하위 그룹 및 문서 없음)만 삭제 가능
  • 하위 정리: 하위 그룹이 있으면 먼저 하위 그룹부터 삭제 필요
  • 문서 보존: 그룹 삭제 시 포함된 문서는 유지됨

💡 팁: 프로젝트별, 부서별, 주제별로 그룹을 구성하면 챗봇이 더 정확한 답변을 제공할 수 있습니다.

🏢 조직 관리 ▼

🏗️ 조직 생성 및 관리

  • 조직 생성: 시스템 관리자만 새로운 조직을 생성할 수 있습니다
  • 조직 정보: 조직명, 설명, 생성일, 멤버 수, 그룹 수 등을 관리
  • 조직 수정: 조직 선택 후 상세 정보에서 이름과 설명 수정 가능
  • 조직 삭제: 멤버가 없는 빈 조직만 삭제 가능 (안전장치)

👥 멤버 관리

  • 멤버 추가: 조직 상세 화면에서 사용자를 조직에 할당
  • 1:1 관계: 각 사용자는 하나의 조직에만 속할 수 있음
  • 멤버 제거: 조직에서 사용자 제거 시 기본 조직으로 이동
  • 멤버 목록: 조직별 소속 멤버를 실시간으로 확인 가능

👑 조직 관리자

  • 역할: 자신의 조직 내에서만 그룹 및 문서 관리 가능
  • 권한 승격: 시스템 관리자가 일반 사용자를 조직 관리자로 승격
  • 권한 해제: 조직 관리자를 일반 사용자로 강등 가능
  • 제한 범위: 조직 관리자는 다른 조직의 데이터에 접근 불가

🔒 접근 권한 제어

  • 문서 격리: 사용자는 자신의 조직에 속한 문서만 검색 가능
  • 그룹 격리: 조직별로 그룹이 분리되어 다른 조직의 그룹은 표시 안 됨
  • 검색 필터링: 검색 시 자동으로 조직 범위로 필터링
  • 보안 강화: 조직 간 데이터 누수 방지 및 멀티 테넌트 지원

🎯 사용 시나리오

  • 부서별 운영: 인사부, 재무부, 개발부 등 부서별로 조직 생성
  • 프로젝트 단위: 각 프로젝트를 독립된 조직으로 관리
  • 고객사별: 여러 고객사의 문서를 안전하게 분리 관리
  • 권한 위임: 부서장을 조직 관리자로 지정하여 자율적 관리

💡 조직 관리 활용 팁:

• 조직별로 문서와 그룹을 분리하면 검색 정확도가 향상됩니다
• 조직 관리자에게 권한을 위임하여 효율적인 분산 관리가 가능합니다
• 기본 조직은 삭제할 수 없으며, 모든 신규 사용자는 기본 조직에 할당됩니다

⚠️ 주의사항: 사용자를 다른 조직으로 이동하면 기존 조직의 문서와 그룹에 접근할 수 없게 됩니다. 이동 전 중요 데이터를 백업하세요.

🤖 모델 설정 ▼

🚀 백엔드 선택

  • Ollama: 로컬 서버에서 실행되는 오픈소스 LLM (빠르고 안정적)
  • Local: Python 환경에서 직접 실행 (설정 유연성 높음)
  • 전환 방법: 백엔드 변경 후 모델 목록 자동 새로고침

🧠 LLM 모델

  • 역할: 사용자 질문에 대한 답변 생성
  • 추천 모델: llama3.2, qwen2.5, gemma2 (한국어 지원 우수)
  • 성능 vs 속도: 파라미터 수가 클수록 성능 좋지만 느림

🔗 임베딩 모델

  • 역할: 문서를 벡터로 변환하여 검색 가능하게 함
  • 추천 모델: nomic-embed-text, bge-m3 (다국어 지원)
  • 중요: 임베딩 모델 변경 시 반드시 "재색인" 필요

⚠️ 주의: 임베딩 모델을 변경한 경우 "재색인" 탭에서 모든 문서를 다시 색인해야 합니다.

⚙️ 시스템 설정 ▼

🔒 자동 로그아웃

  • 기능: 일정 시간 동안 활동이 없으면 자동 로그아웃
  • 설정 범위: 5분 ~ 120분 (기본값: 30분)
  • 보안 강화: 공용 PC에서 사용 시 권장

💾 캐시 설정

  • 기능: 동일한 질문에 대한 답변 재사용으로 속도 향상
  • 캐시 초기화: 문제 발생 시 또는 문서 업데이트 후 권장
  • 통계 확인: 캐시 히트 수로 효율성 확인 가능

📝 시스템 프롬프트 (3-프롬프트 시스템)

  • 역할: AI의 성격, 답변 방식, 제약사항 정의
  • 3가지 프롬프트 유형:
    • 일반 검색용 (Basic): 로컬 문서만 사용하는 검색에 적용
      • 로컬 문서 기반 정확한 답변 제공
      • 문서에 없는 내용은 명시적으로 표시
      • 출처 표시 필수
    • 하이브리드 검색용 (Hybrid): 웹 검색 또는 공식 문서를 포함하는 검색에 적용
      • 로컬 + 웹 + 공식 문서 통합 답변
      • 정보 출처를 [로컬 문서], [웹 검색], [공식 문서]로 구분
      • 최신 정보와 공식 문서 적극 활용
    • 외부 도구 전용 (Tools Only): 웹/공식 문서만 사용하는 검색에 적용
      • 로컬 문서 없이 외부 정보만 활용
      • 최신 정보와 공식 문서 중심 답변
      • 웹 검색과 공식 문서 결과 비교 및 통합
  • 자동 선택: 사용자가 선택한 검색 모드에 따라 자동으로 적절한 프롬프트 적용
  • 커스터마이징: 각 프롬프트를 독립적으로 수정하여 검색 모드별 답변 스타일 조정 가능
  • 유효성 검증: 프롬프트는 비어있을 수 없으며, 최대 10,000자 제한

💾 자동 저장 기능 (NEW):

모든 시스템 설정값(자동 로그아웃 시간, 캐시 설정 등)은 값 변경 즉시 자동으로 저장됩니다. 별도로 "저장" 버튼을 누를 필요가 없어 편리하게 설정을 관리할 수 있습니다.

💡 프롬프트 관리 팁: 시스템 프롬프트를 수정한 후에는 새로운 대화에서만 적용됩니다. 기존 대화는 영향받지 않습니다. 각 검색 모드에 맞게 프롬프트를 세밀하게 조정하여 최적의 답변 품질을 얻을 수 있습니다.

🔄 문서 재색인 ▼

📌 재색인이 필요한 경우

  • 임베딩 모델 변경: 새 모델로 모든 문서 재처리 필요
  • 검색 정확도 저하: 검색 결과가 부정확하거나 이상할 때
  • 대량 문서 업로드: 많은 문서 추가 후 일괄 재색인
  • 시스템 업그레이드: 시스템 업데이트 후 호환성 확보

⚡ 재색인 프로세스

  • 1단계: "재색인 시작" 버튼 클릭
  • 2단계: 진행률 바에서 실시간 진행 상황 확인
  • 3단계: 완료 시 자동으로 완료 메시지 표시
  • 중지 가능: "재색인 중지" 버튼으로 언제든 중단 가능

⏱️ 소요 시간

  • 문서 수: 문서가 많을수록 시간 증가
  • 문서 크기: 대용량 PDF는 처리 시간 길어짐
  • 예상 시간: 화면에 실시간으로 남은 시간 표시
  • 백그라운드: 재색인 중에도 챗봇 정상 사용 가능

🔄 자동 복구 기능 (NEW)

  • 자동 만료: 에러 발생 시 1시간 후 진행 상태 자동 초기화
  • 무한 폴링 방지: 에러 상태가 영구히 남지 않도록 TTL 적용
  • 수동 초기화: 필요시 진행 상태를 즉시 초기화 가능
  • 안정성 향상: 서버 재시작 없이 자동으로 정상 상태 복구

📋 문서 버전 자동 생성 (NEW)

  • 자동 V1 생성: 재색인 시 버전이 없는 문서는 자동으로 V1 버전 생성
  • 중복 방지: 이미 버전이 있는 문서는 건너뛰어 중복 생성 방지
  • 청크 수 기록: 각 버전에 청크 개수를 자동으로 기록
  • 시스템 코멘트: "Initial version (created during reindex)" 코멘트 자동 추가
  • 버전 관리: 재색인 후 모든 문서의 버전 관리가 즉시 시작됨

📋 버전 자동 생성 혜택:

재색인 시 모든 문서에 자동으로 버전이 생성되므로, 이후 문서 수정 시 변경 이력을 추적할 수 있습니다. 문서 관리 탭에서 각 문서의 버전 목록과 변경 이력을 확인할 수 있으며, 필요 시 이전 버전으로 롤백이 가능합니다.

💡 자동 복구 기능:

재색인 중 에러가 발생해도 1시간 후 자동으로 정상 상태로 복구됩니다. 긴급한 경우 재색인 탭의 "진행 상태 초기화" 버튼으로 즉시 초기화할 수 있습니다.

⚠️ 주의: 재색인 중에는 새로운 문서를 업로드하지 마세요. 완료 후 업로드를 권장합니다.

🔍 하이브리드 검색 (Hybrid RAG) ▼

🌐 하이브리드 검색이란?

  • 정의: 로컬 문서 검색 + 웹 검색 + 공식 문서 검색을 결합한 통합 검색 시스템
  • 목적: 로컬 문서에 없는 최신 정보나 공식 문서를 함께 제공
  • 활성화: "시스템 설정" 탭에서 Hybrid RAG 활성화 토글로 켜고 끄기 가능
  • 선택적 사용: 웹 검색과 공식 문서 검색을 각각 독립적으로 활성화 가능

📊 검색 모드 종류

🎯 Smart (스마트)
  • 질문을 자동 분석하여 최적의 검색 소스 선택
  • 로컬 문서에 답이 있으면 로컬만, 없으면 웹/공식문서 추가
  • 대부분의 경우 권장되는 기본 모드
📚 Local Only (로컬 전용)
  • 업로드된 로컬 문서에서만 검색
  • 외부 정보 없이 내부 문서만 참조할 때 사용
  • 가장 빠른 응답 속도
🌐 Web Enhanced (웹 강화)
  • 로컬 문서 + 웹 검색 결과 통합
  • 최신 뉴스, 트렌드, 실시간 정보 필요할 때
  • Tavily (클라우드) 또는 SearXNG (자체 호스팅) 선택 가능
🔬 Comprehensive (종합)
  • 로컬 + 웹 + 공식 문서 모두 검색
  • 가장 포괄적인 정보 제공
  • 기술 질문, 프레임워크 관련 질문에 최적

🔧 검색 소스 설정

  • 로컬 문서: 항상 기본으로 검색됨 (비활성화 불가)
  • 웹 검색 프로바이더:
    • Tavily (클라우드): 빠르고 안정적인 클라우드 기반 웹 검색
      • API 키 필요 (tavily.com에서 발급)
      • 간편한 설정, 별도 인프라 불필요
    • SearXNG (자체 호스팅): 메타 검색 엔진 + Crawl4AI 연동
      • Google, Bing, DuckDuckGo, GitHub, StackOverflow 등 통합
      • Crawl4AI로 웹 페이지 전체 내용 추출 (27~125배 더 많은 콘텐츠)
      • 외부 API 의존 없이 완전 자체 운영 가능
      • docker compose -f docker-compose.searxng.yml up -d 로 시작
  • 공식 문서 (Context7):
    • React, Vue, Spring Boot 등 프레임워크 공식 문서
    • 기술 질문 시 정확한 공식 문서 제공
    • API 키 필요 (시스템 설정에서 입력)

📝 문서 필터링 기능

  • 특정 문서 선택: 검색 전 문서를 선택하면 해당 문서만 검색
  • 그룹 선택: 특정 그룹 선택 시 해당 그룹 내 문서만 검색
  • 하이브리드 검색과 조합: 선택한 문서/그룹 + 웹/공식문서 통합 검색
  • 정확도 향상: 검색 범위를 좁혀 더 정확한 답변 제공

⚡ 사용 시나리오

시나리오 1: 내부 규정 질문
  • 검색 모드: Local Only
  • 이유: 회사 내부 문서만 참조해야 함
  • 예시: "우리 회사 휴가 규정은?"
시나리오 2: 최신 기술 트렌드
  • 검색 모드: Web Enhanced
  • 이유: 최신 정보는 웹에만 존재
  • 예시: "2024년 AI 트렌드는?"
시나리오 3: 프레임워크 사용법
  • 검색 모드: Comprehensive
  • 이유: 로컬 코드 + 공식 문서 조합
  • 예시: "React useEffect 사용법은?"

🔒 관리자 제어 기능 (NEW)

  • 하이브리드 RAG 활성화/비활성화:
    • 시스템 설정에서 하이브리드 RAG 기능을 전체 시스템 차원에서 켜고 끌 수 있음

  • 실시간 상태 동기화:
    • 관리자가 설정을 변경하면 사용자 화면이 즉시 반영 (페이지 새로고침 필요 없음)
    • 사용자가 설정 패널을 열 때마다 최신 상태를 서버에서 확인
    • 검색 모드 변경 시도 시에도 실시간으로 허용 여부 검증
  • 보안 및 비용 관리:
    • 외부 API 사용을 관리자가 중앙에서 제어하여 비용 관리
    • 민감한 내부 정보만 다루는 조직은 하이브리드 RAG를 끄고 로컬 검색만 사용
    • 필요시 관리자가 API 키를 제거하지 않고도 기능 비활성화 가능

• 사용자에게 "하이브리드 RAG 기능이 비활성화되어 있습니다" 경고 표시
• 관리자가 다시 활성화하면 사용자가 모든 검색 모드를 자유롭게 선택 가능

🔧 문제 해결 (Troubleshooting) ▼

❌ 문서 업로드 실패

  • 원인: 파일 형식 미지원, 파일 손상, 용량 초과
  • 해결: 파일 형식 확인, 파일 재다운로드, 파일 분할

❌ 검색 결과 없음

  • 원인: 문서 미업로드, 검색어 오타, 임베딩 미완료
  • 해결: 문서 목록 확인, 검색어 재입력, 재색인 실행

❌ 챗봇 응답 느림

  • 원인: 대용량 문서, 느린 모델, 캐시 미사용
  • 해결: 더 작은 모델 선택, 캐시 활성화, 문서 분할

❌ 재색인 에러 상태 지속 (NEW)

  • 증상: "오류 발생" 상태가 계속되며 무한 폴링
  • 자동 해결: 1시간 후 자동으로 진행 상태 초기화됨
  • 수동 해결: 재색인 탭의 "진행 상태 초기화" 버튼 클릭
  • 예방: TTL 기반 자동 만료로 영구 에러 상태 방지

❌ 모델 목록 로드 실패

  • 원인: Ollama 서버 미실행, 네트워크 문제
  • 해결: Ollama 서버 실행 확인, 연결 상태 점검

❌ 문서 메타데이터를 찾을 수 없습니다 (NEW)

  • 증상: 그룹 관리에서 문서 목록에 "문서 메타데이터를 찾을 수 없습니다" 오류 표시
  • 원인: 문서 파일은 존재하지만 VectorDB 인덱싱이 실패한 상태 (indexed: False)
  • 확인 방법:
    • 문서 목록에서 해당 문서의 "청크 수"가 0으로 표시됨
    • 문서는 보이지만 클릭 시 메타데이터 오류 발생
    • 검색해도 해당 문서 내용이 나오지 않음
  • 해결 방법:
    • 방법 1 (권장): 관리자 페이지 → "재색인" 탭 → "문서 재인덱싱" 버튼 클릭하여 전체 문서 재인덱싱
    • 방법 2: 해당 문서를 그룹에서 제거 → 문서 삭제 → 원본 파일 재업로드
    • 방법 3 (임시): 해당 문서를 그룹에서만 제거 (UI 오류 제거, 파일은 유지)
  • 예방:
    • 대용량 파일(50MB 이상) 업로드 시 처리 완료까지 대기
    • 업로드 후 "청크 수"가 0이 아닌지 확인
    • 임베딩 모델 변경 시 즉시 재색인 실행

❌ 선택한 문서가 검색되지 않음 (NEW)

  • 증상: 특정 문서를 선택하고 검색했는데 선택하지 않은 다른 문서가 결과에 나옴
  • 원인: 문서 필터가 제대로 적용되지 않은 경우 (버전 2.0 이전)
  • 해결:
    • 브라우저 새로고침 (Ctrl+F5 또는 Cmd+Shift+R)
    • 브라우저 캐시 삭제 후 재접속
    • 최신 버전으로 업데이트 (2.0 이상에서 수정됨)
  • 확인 방법: 검색 결과의 "참고 문서" 섹션에서 선택한 문서만 표시되는지 확인

❌ 하이브리드 검색이 작동하지 않음

  • 증상: Hybrid RAG를 활성화했는데 웹 검색이나 공식 문서 검색 결과가 나오지 않음
  • 원인:
    • Tavily API 키 미설정 (Tavily 사용 시)
    • SearXNG 서비스 미실행 또는 URL 미설정 (SearXNG 사용 시)
    • 웹 검색/공식 문서 검색 개별 토글이 꺼져있음
    • 검색 모드가 "Local Only"로 설정됨
  • 해결 (Tavily):
    • "시스템 설정" 탭 → Hybrid RAG 설정 → Tavily API 키 입력
    • 웹 검색 프로바이더를 "Tavily"로 선택
  • 해결 (SearXNG):
    • SearXNG 서비스 실행 확인: docker ps | grep searxng
    • SearXNG 헬스 체크: curl http://localhost:8888/healthz
    • "시스템 설정" → 웹 검색 프로바이더를 "SearXNG (자체 호스팅)"로 선택
    • SearXNG URL 설정 (기본: http://localhost:8888)
    • Crawl4AI 실행 확인: curl http://localhost:11235/health
  • 확인: 검색 결과에 "웹 검색 결과" 또는 "공식 문서" 섹션이 표시되는지 확인

❌ SearXNG 검색 에러 (NEW)

  • 증상: SearXNG 사용 시 특정 엔진에서 JSON 파싱 에러 발생
  • 원인: 일부 검색 엔진(예: Startpage)이 JSON 응답을 올바르게 반환하지 않음
  • 해결:
    • SearXNG 로그 확인: docker logs searxng --tail 50
    • 문제 엔진 비활성화: searxng/settings.yml에서 해당 엔진 disabled: true 설정
    • SearXNG 재시작: docker compose -f docker-compose.searxng.yml restart
  • 정상 작동 엔진: Google, Bing, DuckDuckGo, Brave, Wikipedia, GitHub, StackOverflow

🔑 2단계 인증 (2FA/TOTP) ▼

📱 2FA란?

  • 정의: 비밀번호 외에 추가 인증 수단을 요구하는 보안 방식
  • TOTP: Time-based One-Time Password - 시간 기반 일회용 비밀번호
  • 인증 앱: Google Authenticator, Microsoft Authenticator 등 지원

⚙️ 시스템 설정

  • 2FA 활성화: 시스템 전체에서 2FA 기능 사용 여부 설정
  • 강제 적용: 모든 사용자에게 2FA를 의무화할지 선택
  • 발급 제어: 관리자가 사용자별 2FA 상태 관리

👤 사용자별 관리

  • 상태 확인: 사용자 목록에서 2FA 활성화 상태 확인
  • 초기화: 사용자가 기기를 분실한 경우 관리자가 TOTP 초기화
  • 재설정: 초기화 후 사용자가 새로운 QR 코드로 재등록

🔄 사용자 등록 과정

  1. 프로필 메뉴에서 "2FA 설정" 선택
  2. QR 코드를 인증 앱으로 스캔
  3. 앱에서 생성된 6자리 코드 입력하여 확인
  4. 이후 로그인 시 비밀번호 + TOTP 코드 함께 입력

⚠️ 주의: 2FA를 초기화하면 사용자는 다시 QR 코드를 스캔하여 새로 등록해야 합니다. 초기화 전 사용자에게 미리 안내하세요.

🔌 API 키 관리 ▼

🌐 Tavily API (웹 검색)

  • 용도: 실시간 웹 검색으로 최신 정보 제공
  • 획득: tavily.com에서 무료/유료 API 키 발급
  • 설정: 시스템 설정 → Hybrid RAG → Tavily API 키 입력
  • 무료 제한: 월 1,000회 검색 (유료 플랜으로 확장 가능)
  • 보안: API 키는 암호화되어 저장되며, 마스킹 표시

📚 Context7 API (공식 문서)

  • 용도: React, Vue, Spring Boot 등 프레임워크 공식 문서 검색
  • 획득: context7.com에서 API 키 발급
  • 설정: 시스템 설정 → Hybrid RAG → Context7 API 키 입력
  • 지원 문서: 주요 프로그래밍 언어 및 프레임워크 공식 문서

🔒 API 키 보안

  • 암호화 저장: 모든 API 키는 서버에 암호화되어 저장
  • 마스킹 표시: UI에서 API 키는 일부만 표시 (예: sk-****1234)
  • 전체 보기: "키 보기" 버튼으로 임시로 전체 키 확인 가능
  • 삭제: 필요시 API 키 삭제하여 해당 기능 비활성화

💡 팁: API 키가 없어도 시스템은 정상 작동합니다. Hybrid RAG 기능이 필요한 경우에만 해당 API 키를 설정하세요. 외부 검색이 불필요하면 로컬 문서 검색만으로 충분합니다.

  • 세션 갱신: 사용자 활동 시 자동으로 세션 연장

  • 비밀번호 유출: 계정 침해 의심 시 해당 사용자 전체 세션 종료

⚠️ 주의: 전체 세션 종료 시 모든 사용자가 재로그인해야 합니다. 긴급 상황에서만 사용하고, 사전에 공지하는 것을 권장합니다.

  • 조직 이동: 사용자를 다른 조직으로 이동
  • 계정 잠금/해제: Brute Force 방지로 잠긴 계정 수동 해제
  • 계정 비활성화: 휴직자, 장기 부재자 계정 일시 중지

🔑 비밀번호 관리

  • 비밀번호 재설정:
    • OTP 방식: 이메일로 6자리 인증 코드 전송 (SMTP 설정 필요)
    • 직접 설정: 관리자가 새 비밀번호 직접 지정
  • SMTP 설정: 시스템 설정에서 이메일 서버 구성
  • 비밀번호 정책: 최소 8자, 대/소문자, 숫자, 특수문자 포함 권장

📧 이메일(SMTP) 설정

  • 용도: 비밀번호 재설정 OTP 이메일 발송
  • 설정 항목: SMTP 서버, 포트, 사용자명, 비밀번호, 발신자 정보
  • 테스트: 설정 후 "연결 테스트" 버튼으로 확인
  • Gmail 예시: smtp.gmail.com, 포트 587, 앱 비밀번호 사용
  • 캐싱: SMTP 설정은 5분간 캐시되어 성능 최적화

💡 팁: Gmail을 SMTP로 사용할 경우, 일반 비밀번호가 아닌 "앱 비밀번호"를 생성하여 사용해야 합니다. Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호에서 생성할 수 있습니다.

❔ 자주 묻는 질문 (FAQ) ▼

Q: 문서를 업로드하면 바로 검색이 가능한가요?

A: 네, 업로드 즉시 자동으로 텍스트 추출 및 임베딩이 생성되어 바로 검색 가능합니다. 단, 대용량 파일은 처리에 1-2분 소요될 수 있습니다.

Q: 하나의 문서를 여러 그룹에 추가할 수 있나요?

A: 네, 가능합니다. 하나의 문서는 여러 그룹에 동시에 포함될 수 있어 유연한 분류가 가능합니다.

Q: 임베딩 모델을 변경하면 어떻게 되나요?

A: 임베딩 모델 변경 시 반드시 "재색인" 탭에서 모든 문서를 재색인해야 합니다. 재색인하지 않으면 검색이 정상적으로 작동하지 않을 수 있습니다.

Q: 재색인은 얼마나 자주 해야 하나요?

A: 일반적으로 임베딩 모델 변경 시에만 필요합니다. 단순 문서 추가/삭제는 자동으로 처리되므로 재색인이 불필요합니다.

Q: 업로드한 문서는 어디에 저장되나요?

A: 문서는 서버의 `data/` 디렉토리에 저장되며, 텍스트 추출 후 임베딩은 Redis 벡터 데이터베이스에 저장됩니다.

Q: 한글 파일명 검색이 안 되는데 어떻게 해야 하나요?

A: 최신 버전에서는 한글 검색이 정상 작동합니다. 문제가 계속되면 브라우저 캐시를 삭제하고 페이지를 새로고침해 주세요.

Q: Hybrid RAG와 일반 검색의 차이는 무엇인가요?

A: 일반 검색은 업로드된 로컬 문서만 검색합니다. Hybrid RAG는 로컬 문서 + 웹 검색(Tavily) + 공식 문서(Context7)를 통합하여 더 포괄적인 정보를 제공합니다. 최신 정보나 기술 문서가 필요할 때 Hybrid RAG를 활성화하세요.

Q: 어떤 검색 모드를 사용해야 하나요?

A: Smart 모드를 권장합니다. 자동으로 질문을 분석하여 최적의 검색 소스를 선택합니다. 내부 문서만 필요하면 Local Only, 최신 정보가 필요하면 Web Enhanced, 기술 질문은 Comprehensive 모드를 사용하세요.

Q: Tavily나 Context7 API 키가 없으면 어떻게 되나요?

A: API 키가 없어도 시스템은 정상 작동합니다. Hybrid RAG를 활성화해도 API 키가 없으면 자동으로 로컬 문서만 검색합니다. 웹 검색이나 공식 문서 검색이 필요한 경우에만 해당 API 키를 설정하세요.

Q: 특정 문서만 선택해서 검색할 수 있나요?

A: 네, 가능합니다. 검색 전 문서 필터에서 특정 문서나 그룹을 선택하면 해당 문서만 검색합니다. Hybrid RAG와 조합하면 선택한 문서 + 웹/공식문서를 함께 검색할 수 있습니다.

Q: 문서 메타데이터를 찾을 수 없다는 오류가 나오는데 어떻게 해야 하나요?

A: 문서 파일은 존재하지만 인덱싱이 실패한 경우입니다. "재색인" 탭에서 "문서 재인덱싱" 버튼을 클릭하여 전체 문서를 재인덱싱하거나, 해당 문서를 삭제 후 재업로드하세요. 상세한 해결 방법은 "문제 해결" 섹션을 참고하세요.

🔄 RAG (검색 증강 생성) 시스템

1. 문서 임베딩 (Document Embedding)
  • 업로드된 문서를 작은 청크(chunk)로 분할
  • 각 청크를 임베딩 모델로 벡터화
  • 벡터를 Redis 벡터 데이터베이스에 저장
  • 메타데이터(파일명, 그룹, 페이지 등) 함께 저장
2. 의미 검색 (Semantic Search)
  • 사용자 질문을 동일한 임베딩 모델로 벡터화
  • 코사인 유사도로 관련 문서 청크 검색
  • 그룹 필터링 적용 (선택 시)
  • 상위 N개의 가장 관련성 높은 청크 추출
3. 답변 생성 (Answer Generation)
  • 검색된 문서 청크를 컨텍스트로 제공
  • LLM 모델이 컨텍스트 기반 답변 생성
  • 스트리밍 방식으로 실시간 응답 전달
  • 출처(source) 정보와 함께 제공
