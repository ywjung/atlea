# 프롬프트 엔지니어링 가이드

## 📋 개요

이 문서는 ATLEA의 프롬프트 개선 내역과 설계 원칙을 설명합니다.

### 변경 이력
- **2025-12-28**: 구조화된 프롬프트로 전면 개선

## 🎯 개선 목표

### 1. 환각(Hallucination) 방지
**문제**: LLM이 문서에 없는 정보를 만들어내는 현상

**해결책**:
```
✅ 명시적 규칙 추가:
- "제공된 문서만 사용"
- "추측 금지"
- "불확실하면 '정보 없음' 명시"

❌ 금지 사항 명확화:
- 일반 지식 사용 금지
- 추측성 표현 금지
- 구체적 정보 생성 금지
```

**효과**: 환각 발생률 50% 감소 (예상)

---

### 2. 구조화된 답변
**문제**: 답변 형식이 일관되지 않음

**해결책**: 질문 유형별 템플릿 제공

#### HOW-TO 질문 템플릿
```markdown
## [작업명]

### 준비사항
- 필요한 도구/환경

### 단계별 진행
1. [첫 번째 단계]
   - 세부 내용
   - 주의사항

### 확인 방법
- 정상 동작 확인 기준

[출처]
```

#### 계산/수치 질문 템플릿
```markdown
### 적용 규칙
"[문서 원문]" [출처]

### 계산 과정
1. 기본값: X
2. 추가: Y
3. 결과: **Z**

[출처]
```

**효과**: 답변 가독성 및 일관성 향상

---

### 3. 출처 명시 강화
**문제**: 정보의 출처가 불명확함

**해결책**:
```markdown
## 규칙
- 각 주장마다 [문서명] 표시
- 직접 인용 시 따옴표 사용
- 답변 말미에 참고 문서 목록

## 예시
Spring Boot는 자동 설정을 제공합니다 [spring-boot-reference.pdf].

📚 참고 문서:
- spring-boot-reference.pdf: 자동 설정 메커니즘
```

**효과**: 답변 신뢰도 향상

---

### 4. 정보 부족 시 명확한 안내
**문제**: 정보가 없을 때 막연한 답변

**해결책**: 표준 응답 형식
```markdown
제공된 문서에는 [질문 내용]에 대한 정보가 없습니다.

필요한 정보:
- [정보1]
- [정보2]

관련 문서를 추가로 제공해주세요.
```

**효과**: 사용자가 무엇을 추가해야 할지 명확히 알 수 있음

## 📊 프롬프트 구조

### System Prompt (역할 정의)
```
1. 역할 정의 (🎯)
   - 문서 기반 QA 전문가
   - 정확성 우선
   - 이해하기 쉬운 설명

2. 필수 규칙 (⚠️)
   - 환각 방지
   - 정보 부족 시 대응
   - 출처 명시

3. 답변 구조 가이드 (📋)
   - 기본 형식
   - HOW-TO 템플릿
   - 계산 템플릿
   - 비교 템플릿

4. 특수 상황 처리 (🔍)
   - 코드 예제
   - 전문 용어
   - 다중 문서 종합
   - 대화 맥락

5. 품질 기준 (✨)
   - 정확성
   - 명확성
   - 완전성
   - 전문성

6. 체크리스트 (📝)
   - 자체 검증 항목
```

### User Prompt (질문 + 컨텍스트)
```markdown
=== 📚 참고 문서 (N개) ===

[문서 1]
📄 파일명: example.pdf
🎯 관련도: 95%
📝 내용:
...

=== ❓ 사용자 질문 ===
[질문 내용]

=== ✍️ 답변 작성 ===
위 문서의 정보만을 사용하여 정확하고 구조화된 답변을 작성하세요.
```

## 🔧 컨텍스트 포맷 개선

### 이전 (Before)
```python
context_text = "\n\n".join([
    f"[문서: {doc['filename']}]\n{doc['text']}"
    for doc in context
])
```

### 개선 (After)
```python
for idx, doc in enumerate(context, 1):
    score = doc.get('score', 0)
    score_percent = int(score * 100)

    context_part = f"""[문서 {idx}]
📄 파일명: {doc['filename']}
🎯 관련도: {score_percent}%
📝 내용:
{doc['text']}
---"""
```

**개선점**:
- 문서 번호 추가 (참조 용이)
- 관련도 점수 표시 (신뢰도 판단)
- 구분선으로 가독성 향상

## 🎓 학습 포인트

### LLM 동작 원리
- 프롬프트는 LLM의 "프로그래밍 언어"
- 명시적 규칙이 성능을 결정
- 구조화가 일관성을 보장

### 효과적인 프롬프트 설계
1. **명확성**: 모호함 제거
2. **구조성**: 템플릿 제공
3. **제약성**: 규칙 명시
4. **검증성**: 체크리스트 포함

### 반복적 개선
- 테스트 → 측정 → 개선 → 반복
- 사용자 피드백이 핵심
- A/B 테스트로 검증
